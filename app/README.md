# UMKA — приложение

Автономная сортировка мусора: USB-камера, модель YOLO, два сервопривода через
PCA9685 и веб-интерфейс на порту 3000. Этот каталог целиком копируется на
устройство в `~/app` — см. [deploy/README.md](../deploy/README.md).

## Состав

| Путь | Назначение |
| --- | --- |
| `app.py` | точка входа |
| `best.pt` | обученная модель YOLO |
| `sorter/` | камера, распознавание, автомат сортировки, механизм, веб-сервер |
| `web/` | главный экран, демонстрация, настройки |
| `tools/` | калибровка и проверки оборудования отдельно от приложения |
| `kiosk_launcher.py` | Chromium во весь экран на подключённом дисплее |
| `tests/` | тесты без камеры, модели и моторов |
| `requirements.txt`, `requirements-opi.txt` | зависимости; PyTorch ставит установщик |

На устройстве дополнительно появляются `umka.conf` (параметры этой платы),
`data/` (статистика, журналы, настройки) и `.venv/` — они не хранятся в git.

## Запуск

```bash
cd ~/app && .venv/bin/python app.py
```

Драйвер моторов, каналы и камера берутся из `umka.conf`; любой параметр можно
переопределить: `--hardware console|pca9685|gpiozero`, `--camera N`,
`--tilt-channel N`, `--rotate-channel N`, `--i2c-bus N`, `--port 3000`,
`--confidence 0.60`, `--stable-frames 5`, `--clear-frames 10`, `--verbose`.
`--hardware console` — работа без моторов: сброс только пишется в журнал.

## Страницы

| Адрес | Что там |
| --- | --- |
| `/` | главный экран для посетителей: ожидание, распознанный тип, вопрос «Да/Нет» |
| `/camera.html` | демонстрация: видео с рамками, что видит модель, состояние |
| `/settings.html` | настройки (во время работы сортировка на паузе) |

На главном экране **пять касаний логотипа за 4 секунды** включают режим
разработчика: панель «Настройки», «Демонстрация», «Отладка» (живые данные поверх
экрана), «Закрыть экран» и «Выйти из режима». Режим сохраняется при переходах
между страницами и сам выключается через 15 минут без касаний.

Вкладки настроек:

- **Экран** — подтверждение распознавания «Да/Нет» или показ результата с
  полосой времени; разрешение дисплея, которое UMKA удерживает после
  переподключения;
- **Моторы** — выключить неисправный или перегретый мотор (сигнал снимается сразу);
- **Центр**, **Секции** — углы покоя и сброса в каждую секцию, «Проверить сброс»;
- **Камера** — яркость, контраст, гамма и другие параметры камеры;
- **Область распознавания** — часть кадра, где модель ищет предметы;
- **Пустая площадка** — набор снимков пустой площадки против ложных срабатываний;
- **Датасет** — сбор кадров для дообучения во время работы и выгрузка архивом.

Всё, кроме углов, сохраняется сразу; углы — кнопкой «Сохранить углы».

## Как принимается решение

1. Камера читает кадры в отдельном потоке; модель смотрит только в
   область распознавания.
2. Классы `hand` и `empty` игнорируются; рамка, совпадающая со снимком пустой
   площадки, отсеивается.
3. Один и тот же класс в `stable_frames` кадрах подряд запускает сброс в
   секцию по `AppConfig.class_to_section` в [sorter/config.py](sorter/config.py):
   бумага → 4, пластик → 3, органика → 2, остальное → 1.
4. Следующий сброс возможен, когда площадка пуста `clear_frames` кадров подряд.

## Калибровка и проверки

Перед запуском этих утилит остановите UMKA: камера и PCA9685 не делятся между
процессами.

```bash
.venv/bin/python tools/check_camera.py           # кадр, частота, засветка
.venv/bin/python tools/check_servo.py --channel 0  # один мотор: углы, проход, off
.venv/bin/python tools/calibrate.py              # сброс по секциям: 1–4, c, q
```

Порядок поэтапной проверки — [docs/hardware.md](../docs/hardware.md).

## Данные

| Файл в `data/` | Содержимое |
| --- | --- |
| `sort_stats.json` | счётчики и примерная масса (оценка по классу, не весы) |
| `events/events.jsonl` | история сортировок и ответов, 30 дней |
| `logs/umka.log` | журнал, ротация ежедневно, 14 дней |
| `servo_calibration.json` | углы и включённые моторы со страницы настроек |
| `crop.json`, `camera_controls.json`, `display.json`, `screen.json` | область, параметры камеры, режим экрана, разрешение дисплея |
| `empty_platform/*.png` | снимки пустой площадки (пригодятся и для дообучения модели) |
| `dataset/{confirmed,rejected,unverified,background}/` | кадры для дообучения: `.jpg`, разметка YOLO `.txt`, сведения `.json` |

## API

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/state`, `GET /api/health` | состояние и диагностика |
| `GET /api/camera.mjpg` | видео с разметкой |
| `POST /api/feedback` | ответ «Да/Нет»: `{"answer": "yes", "eventId": "..."}` |
| `GET/POST /api/display` | режим главного экрана |
| `GET/POST /api/screen` | разрешение дисплея (xrandr) |
| `GET /api/calibration`, `POST /api/calibration/{mode,move,test,save,motor}` | настройка механизма |
| `GET/POST /api/camera/controls`, `POST /api/camera/controls/reset` | параметры камеры |
| `GET/POST /api/crop` | область распознавания |
| `GET/POST /api/dataset`, `POST /api/dataset/clear`, `GET /api/dataset/export` | сбор датасета, ZIP-архив |
| `GET/POST /api/background`, `POST /api/background/{delete,clear}`, `GET /api/background/thumbnail?id=` | снимки пустой площадки |

## Тесты

```bash
python -m unittest discover -s tests -v   # из каталога app/
node --test tests/test_feedback_ui.cjs     # переходы главного экрана
```

Тесты фильтра пустой площадки требуют OpenCV и на компьютере без него
пропускаются; на устройстве выполняются все.
