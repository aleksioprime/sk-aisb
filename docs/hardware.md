# Оборудование и поэтапная сборка

## Состав

- Raspberry Pi 4/5 или Orange Pi 5/5B с 64-битной системой;
- USB-камера (проверена GEMBIRD AX2311, 640×480);
- плата PCA9685 (16 каналов ШИМ, I2C) и два сервопривода:
  **поворот** распределителя и **наклон** площадки;
- отдельный блок питания сервоприводов;
- HDMI-дисплей (необязательно), сенсорный - с USB-кабелем сенсора.

## Подключение PCA9685

Подключайте при выключенном питании. Номера - физические контакты разъёма
GPIO; у Raspberry Pi и Orange Pi 5B они совпадают.

| Контакт платы | PCA9685 |
| --- | --- |
| 1 - 3,3 В | VCC |
| 3 - SDA | SDA |
| 5 - SCL | SCL |
| 6 - GND | GND |

- Питание моторов: плюс отдельного блока → **V+**, минус → **GND** PCA9685.
  Земля общая с платой. **V+ не соединяйте с VCC или питанием платы.**
- Контакт OE - на GND. Адресные перемычки A0–A5 не замыкайте (адрес `0x40`).
- По умолчанию **поворот - канал 0, наклон - канал 1**. На каждом канале:
  сигнал → S/PWM, питание → V+, земля → GND. Если при сборке перепутали -
  не перепаивайте, а укажите каналы в `umka.conf`
  (`deploy/install.sh ... --tilt-channel 0 --rotate-channel 1`).
- Шина: Raspberry Pi - `/dev/i2c-1`, Orange Pi 5/5B - `/dev/i2c-5`
  (оверлей `i2c5-m3`; UART1 на тех же контактах должен быть выключен).
  Установщик включает шину сам.

Ток сервоприводов под нагрузкой - до 1–2 А на мотор. Слабый блок питания
даёт просадки: моторы дрожат, а камера и другие USB-устройства
переподключаются. Проверяйте напряжение на V+ мультиметром во время движения
обоих моторов - для 5-вольтовых сервоприводов не ниже 4,8 В.

Вариант без PCA9685 (только Raspberry Pi): наклон - GPIO 12, поворот -
GPIO 13, `hardware = gpiozero`.

## Камера и дисплей

- Камеру подключайте в USB-порт напрямую, без удлинителей. Если она всё же
  переподключится, UMKA найдёт её заново сама, даже под другим номером.
- HDMI-дисплей 1024×600 на Orange Pi 5B устойчиво работает в режиме
  1280×720 (см. [troubleshooting.md](troubleshooting.md)).
- Сенсор дисплея - отдельный USB-кабель в разъём **Touch** дисплея
  (не **Power**), и кабель должен передавать данные, а не только заряжать.

## Поэтапная сборка

Не собирайте всё сразу: проверяйте каждый узел отдельно, тогда неисправность
видна сразу, а не в виде «ничего не работает».

1. **Плата и система.** Установка по [deploy/README.md](../deploy/README.md),
   перезагрузка, веб-страница `http://<IP>:3000` открывается.
2. **Питание моторов.** Блок питания без нагрузки, затем под нагрузкой:
   напряжение на V+ не проседает.
3. **PCA9685.** `i2cdetect -y 5` (Orange Pi) или `i2cdetect -y 1` (Raspberry
   Pi) показывает `40`.
4. **Каждый сервопривод отдельно, без механизма** (UMKA остановлена):

   ```bash
   cd ~/app && .venv/bin/python tools/check_servo.py --channel 0
   ```

   Команда `s` проводит мотор по всему диапазону. Мотор должен вращаться
   плавно, без гудения и нагрева. `off` - снять сигнал.
5. **Сервоприводы в механизме.** Тем же скриптом найдите крайние углы, в
   которых площадка ещё не упирается в корпус, и запишите их. За этими углами
   мотор стоит под нагрузкой, греется и выходит из строя.
6. **Камера** (UMKA остановлена):

   ```bash
   cd ~/app && .venv/bin/python tools/check_camera.py
   ```

   Снимок в `data/camera-check.jpg`; скрипт показывает долю пересвеченных
   пикселей - ориентир против бликов.
7. **Калибровка сброса.** Запустите UMKA и откройте настройки (пять касаний
   логотипа → «Настройки», или `http://<IP>:3000/settings.html`): центр,
   углы каждой секции в пределах, найденных на шаге 5, «Проверить сброс».
   Консольный вариант - `tools/calibrate.py`.
8. **Распознавание на месте.** Вкладки «Камера», «Область распознавания» и
   «Пустая площадка» в настройках; затем страница «Демонстрация».
