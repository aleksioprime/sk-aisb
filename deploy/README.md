# Установка UMKA на устройство

Установка выполняется **с компьютера по сети**: скрипт копирует приложение на
плату и сам настраивает её. Поддерживаются:

| Плата | Система | Шина I2C для PCA9685 |
| --- | --- | --- |
| Raspberry Pi 5 | Raspberry Pi OS 64-bit (Bookworm) | `/dev/i2c-1` |
| Raspberry Pi 4 | Raspberry Pi OS 64-bit (Bookworm) | `/dev/i2c-1` |
| Orange Pi 5 / 5B | Ubuntu 22.04 Jammy (образ Orange Pi) | `/dev/i2c-5` |

На компьютере нужны `bash`, `ssh` и `rsync` (на macOS и Linux есть сразу; на
Windows — WSL). Подключение оборудования — в [docs/hardware.md](../docs/hardware.md).

## 1. Подготовить доступ по SSH — один раз

Узнайте IP-адрес платы (на самой плате: `hostname -I`) и скопируйте на неё
свой SSH-ключ, чтобы не вводить пароль при каждом подключении:

```bash
ssh-copy-id orangepi@192.168.10.100
```

Без ключа установщик спросит пароль SSH один раз за запуск. Пароль `sudo`
на плате спрашивается в любом случае — для установки системных пакетов.

## 2. Установить

Из корня репозитория:

```bash
deploy/install.sh orangepi@192.168.10.100
```

Установщик:

1. копирует `app/` в `~/app` на плате. Файлы устройства — `data/`
   (статистика, настройки, снимки площадки), `umka.conf` и `.venv` — не
   трогаются, удалённые из репозитория файлы кода удаляются;
2. ставит системные пакеты, включает I2C (на Orange Pi — оверлей `i2c5-m3`),
   добавляет пользователя в группы `video`, `i2c`, `gpio`;
3. создаёт `.venv` и ставит PyTorch, подходящий именно этой плате
   (на Raspberry Pi 4 — версию без `Illegal instruction`), затем зависимости;
4. проверяет, что PyTorch выполняет вычисления на этом процессоре;
5. создаёт `~/app/umka.conf`: если PCA9685 отвечает на шине, драйвер
   `pca9685`, иначе `console` — работа без моторов;
6. кладёт на рабочий стол ярлыки «Запустить UMKA» и «Открыть экран UMKA».

Если установщик включил I2C или добавил пользователя в группы, он попросит
**перезагрузить плату**. После перезагрузки проверьте шину
(`i2cdetect -y 5` на Orange Pi, `i2cdetect -y 1` на Raspberry Pi) — должен
быть адрес `40` — и запустите установщик ещё раз, если `umka.conf` получил
`hardware = console`, а моторы подключены (или передайте `--hardware pca9685`).

### Параметры

| Параметр | Что делает |
| --- | --- |
| `--hardware pca9685\|console\|gpiozero` | драйвер моторов в `umka.conf` |
| `--tilt-channel N`, `--rotate-channel N` | каналы PCA9685 наклона и поворота (по умолчанию 1 и 0) |
| `--camera N` | номер камеры `/dev/videoN` |
| `--i2c-bus N` | номер шины, если плата не определилась сама |
| `--autostart` | служба `umka` (UMKA стартует при включении) и киоск при входе в рабочий стол |
| `--no-autostart` | убрать службу и автозапуск киоска |
| `--code-only` | только код: без системных пакетов и `pip`, быстро и не нагружает плату; `umka.conf`, ярлыки и служба обновляются |
| `--skip-system` | не трогать системные пакеты, I2C и группы |
| `--dest DIR` | каталог на плате вместо `~/app` |
| `--ssh-key FILE`, `--port N`, `--ssh-opt OPT` | параметры SSH |
| `--dry-run` | показать команды, ничего не выполняя |

Пример для устройства, где моторы при сборке подключены наоборот, с
автозапуском:

```bash
deploy/install.sh orangepi@192.168.10.100 --tilt-channel 0 --rotate-channel 1 --autostart
```

## Обновление

После изменений в коде:

```bash
deploy/install.sh orangepi@192.168.10.100 --code-only
```

Если UMKA работает службой, она перезапустится сама; если запущена вручную —
установщик напомнит перезапустить её. Полный запуск без `--code-only` тоже
безопасен: `apt` запускается, только если каких-то пакетов не хватает, а
`pip` лишь проверит установленные версии.

## Параметры устройства: `umka.conf`

`~/app/umka.conf` хранит то, что отличается у конкретной платы. Его читают
`app.py` и все `tools/*.py`, поэтому каналы и камера одинаковы при запуске
службой, ярлыком и вручную по SSH. Аргументы командной строки важнее файла.

```ini
hardware = pca9685
tilt_channel = 1
rotate_channel = 0
camera = 0
# i2c_bus = 5
```

Изменить можно установщиком (`--tilt-channel 0` и т. п.) или вручную на плате,
затем перезапустить UMKA.

## Запуск и остановка

**Служба** (после `--autostart`):

```bash
sudo systemctl restart umka      # перезапустить
sudo systemctl stop umka         # остановить
journalctl -u umka -f            # журнал
```

**Вручную по SSH** (без службы):

```bash
cd ~/app && .venv/bin/python app.py
```

Остановка — `Ctrl+C`. В фоне, чтобы UMKA пережила отключение SSH:

```bash
cd ~/app && setsid -f .venv/bin/python app.py > data/logs/umka-ssh.log 2>&1 < /dev/null
pkill -INT -f '[.]venv/bin/python .*app[.]py'   # остановить
```

**Экран (киоск)** на подключённом дисплее — ярлыком «Открыть экран UMKA» или по SSH:

```bash
DISPLAY=:0 setsid -f python3 ~/app/kiosk_launcher.py > /dev/null 2>&1 < /dev/null
pkill -f '[k]iosk_launcher.py'   # закрыть
```

Киоск ждёт до 60 секунд, пока UMKA ответит, поэтому порядок запуска не важен.
Закрытие киоска не останавливает распознавание.

## Что лежит в каталоге

- [install.sh](install.sh) — запускается на компьютере;
- [setup_device.sh](setup_device.sh) — выполняется на плате (установщик
  копирует его в `~/app/.deploy/`); можно запустить там вручную повторно;
- [templates/](templates/) — служба systemd и ярлыки; пути и пользователь
  подставляются при установке.
